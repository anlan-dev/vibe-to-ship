# Vibe to Ship

> 一个结构化的 AI 辅助开发流程框架，面向"快速原型 + AI 辅助开发"场景。
> 核心目标不是写代码，而是通过**规范文档固化边界**，通过**验收/回滚机制守住底线**，防止失控。

[English](./README.md)

## 核心理念

**用规范文档约束 AI，用验收/回滚保护自己。**

Vibe Coding 不是乱写，而是有节奏地、可撤回地、可验收地快速推进。

| 方式 | 你得到什么 |
|------|-----------|
| 「帮我做一个 app」 | 代码（可能能跑，可能不是你要的） |
| AI 角色扮演 prompt | 一次有趣的对话，没有实际产出 |
| **Vibe to Ship** | 一套有质量门的结构化工作流，SDD 规范驱动 + 验收/回滚机制 |

## 流程总览

```
[1] 产品定位 → [2] 视觉设计 → [3] SDD 固化边界 → [4] 小步迭代开发 → [5] 部署交付
                                    ↓
                           （每个环节都嵌有验收/回滚）
```

| 阶段 | 发生什么 | 谁做决定 | 验收/回滚 |
|------|---------|---------|----------|
| **[1] 产品定位** | AI 脑暴，明确做什么、不做什么、怎么落地 | 你回答，AI 挑战假设 | PRD 草稿产出 |
| **[2] 视觉设计** | 确定设计语言，生成可交付给 AI 的视觉参考 | 你审批设计方向 | UI 原型产出 |
| **[3] SDD 固化边界** | 用 3 份文档"锁死"开发范围、约束和验收标准 | 你审批文档 | PRD.md + DESIGN.md + ARCHITECTURE.md |
| **[4] 小步迭代开发** | 一次只做一件事，每步测试通过再继续 | 你审查每一步 | TODO.md + 验收清单 + 回滚机制 |
| **[5] 部署交付** | 部署、文档、维护 | 你拥有这个产品 | README.md + 环境变量 + 部署链接 |

每个阶段都有**质量门** — 前一阶段不达标，不能进入下一阶段。

---

## [1] 产品定位，形成 PRD 草稿

**目标**：用 AI 脑暴，明确做什么、不做什么、怎么落地。

**操作步骤**：

1. 与 AI 对话，围绕以下问题梳理：
   - 产品解决什么核心问题？目标用户是谁？
   - 用户当前解决方案是什么？有什么不足？
   - 竞品分析：谁在做？我们的差异化（USP）在哪？可以借鉴什么？
   - MVP 必须包含哪些功能？明确黑名单（绝对不做哪些功能）
   - 发布形态：Web / 小程序 / 插件 / App / 内部工具？
   - 算账：API 成本、服务器成本、时间成本是否可控？

2. 技术可行性确认：
   - 前端：React / Vue / Next.js / Vite？
   - 后端/数据库：Supabase / Firebase / 纯前端 LocalStorage？
   - AI 能力：DeepSeek / OpenAI / SiliconFlow / Gemini？
   - 部署：Vercel / Netlify / Cloudflare？
   - 特殊能力：向量数据库 / PDF 解析 / 爬虫？

3. **产出**：PRD.md 草稿（包含定位、用户、痛点、MVP 清单、页面清单、核心流程、技术方案、主要风险）。

---

## [2] 视觉设计：灵感收集 & UI 原型

**目标**：确定设计语言，生成可交付给 AI 的视觉参考。

**操作步骤**：

1. 在 Dribbble、Linear、v0 等平台搜集喜欢的 UI 风格图。
2. 丢给 AI，让它提炼设计关键词（整体气质、色彩、布局、卡片风格、避免事项）。
3. 使用 Figma Make / Figma AI 生成并打磨 UI 原型（用于辅助 Coding Agent 理解产品逻辑和设计风格）。
4. 根据 UI 原型反向修正 PRD（如发现页面流程遗漏，及时补正）。

---

## [3] SDD 固化开发边界（核心环节）

**目标**：在编码开始前，用 3 份文档"锁死"开发范围、约束和验收标准，防止 AI 随意发挥。

**操作**：在项目根目录建立 `docs/` 文件夹，将 PRD 草稿 + UI 设计图喂给 Coding Agent，输出并维护以下 3 份文档：

### 📄 PRD.md

- 产品定位、用户痛点
- 核心用户旅程
- MVP 核心功能列表（明确哪些做）
- 绝对不做的功能黑名单
- 验收标准（全局）

### 📄 DESIGN.md

- 视觉主色调（Tailwind 颜色代码）
- 组件复用规范（按钮、卡片、表单等）
- 关键交互动效（hover、过渡、加载骨架）
- 错误/加载中/空数据状态的视觉表现（统一 UI）

### 📄 ARCHITECTURE.md（开发约束）

- 技术栈（明确版本）
- 目录结构（强制约定）
- 数据模型（TypeScript 接口 / 数据库 schema）
- 服务层约定（API 调用方式、错误处理）
- AI 引用机制（如何调用 AI 接口）
- 开发约束（禁止使用某种写法、禁止改动某类文件）
- 禁止破坏的逻辑（例：不得破坏用户认证流程、不得改变核心计算逻辑）
- 验收标准（每个模块的通过条件）

---

## 🔄 验收/回滚机制（嵌入每一步）

这是"Vibe Coding"真正防失控的关键——每个迭代开始前，必须先写清楚"做完怎么判断"和"坏了怎么撤"。

### 验收标准（每个迭代强制包含）

每个功能模块/任务在开始前，必须明确：

- **主流程**：正常路径操作后的预期结果（如：点击"生成" → 显示结果）
- **加载中**：骨架屏/loading 状态出现
- **为空**：无数据时的占位提示
- **接口报错**：错误提示友好且可重试
- **边界情况**：输入为空、超长、特殊字符等

### 回滚机制（每个迭代强制包含）

- 每次提交前，本地跑通上述验收项。
- 若下一步 AI 把代码写崩且无法轻松修复，立即执行 `git reset --hard` 回到上一个已知正常版本。
- 大需求变更必须先同步更新 PRD.md 和 ARCHITECTURE.md，再加入 TODO.md 清单，避免 MVP 失控。

---

## [4] 正式开发：小步迭代、测试上线

**操作规则**：

1. 让 AI 同时读取 `docs/` 里的规范文档，在根目录生成 TODO.md 清单（按模块拆分任务）。
2. **严禁多任务并行**，按照 TODO.md 的顺序，一次只勾选一个任务。
3. 每轮开发前，AI 必须声明：
   - 修改目标（做什么）
   - 允许修改范围（哪些文件）
   - 不允许破坏的逻辑（哪些不可动）
   - 验收标准（本轮的测试项）
4. 每完成一个模块，进行页面测试（必须测试主流程、加载中、为空、接口报错状态）。
5. 测通后，立即执行：
   ```bash
   git add .
   git commit -m "feat: xxx 通关"
   ```
6. 变更控制：
   - 发现新需求 → 小需求当场修；大需求必须先更新 PRD.md 和 ARCHITECTURE.md，再更新 TODO.md，重新排序优先级。

---

## [5] 部署上线，闭环交付

**操作**：

1. 代码推送到 GitHub，在 Vercel / Netlify / Cloudflare 等平台部署上线。
2. Coding Agent 扫描最终代码，把最新的实际目录结构更新到 ARCHITECTURE.md（保持文档与代码一致）。
3. 生成规范的 README.md（包含项目简介、技术栈、本地启动方式、环境变量、部署链接）。

---

## 核心原则（防失控清单）

| 原则 | 说明 |
|------|------|
| **先文档，后代码** | 没有更新 PRD/ARCHITECTURE 之前，不写大功能 |
| **一次只做一件事** | 严格按照 TODO.md 顺序，绝不并行 |
| **每个迭代必写验收标准** | 主流程、加载、空、报错，四态必测 |
| **随时准备回滚** | 写崩了立刻 `git reset --hard`，不要犹豫 |
| **大变更必须走文档** | 否则 MVP 范围会膨胀，变成"烂尾楼" |

## 快速开始

### 方式一：复制 prompt（任意 AI 平台）

1. 复制 [`prompts/cofounder.md`](./prompts/cofounder.md) 中的 prompt
2. 粘贴到 ChatGPT / Claude / Cursor / 任意 AI
3. 告诉它你想做什么
4. 跟着五阶段走

### 方式二：安装 Trae Skill（推荐 Trae 用户）

```bash
# 将 skill 复制到 Trae skills 目录
cp -r skills/tech-cofounder ~/.trae/skills/
```

然后在 Trae 中说「我想做一个工具」，AI 会自动进入联合创始人模式。

### 方式三：安装为 Claude Code Skill

```bash
# 将 skill 复制到 Claude Code skills 目录
cp -r skills/tech-cofounder ~/.claude/skills/

# 将规则复制到 Claude Code rules 目录
cp -r rules/* ~/.claude/rules/

# 将智能体复制到 Claude Code agents 目录
cp -r agents/* ~/.claude/agents/

# 将命令复制到 Claude Code commands 目录
cp -r commands/* ~/.claude/commands/
```

## 里面有什么

### 规则

确保每个产品都安全、代码规范、经过测试的模块化准则：

| 规则 | 内容 |
|------|------|
| **安全** | 禁止硬编码密钥、输入验证、OWASP 基础、应急协议 |
| **代码风格** | 不可变性、文件组织、命名规范、错误处理 |
| **测试** | TDD 工作流、80% 覆盖率、边界情况测试 |
| **质量** | 阶段门禁、视觉一致性、响应式设计、可访问性 |

### 智能体

可以委派任务的专用子智能体：

| 智能体 | 何时使用 |
|--------|---------|
| **规划者** | 写代码之前 — 创建详细实施计划 |
| **代码审查员** | 写完代码后 — 审查质量、安全、模式 |
| **安全审查员** | 认证/API/支付代码 — OWASP 审计、漏洞检测 |
| **打磨智能体** | 阶段 4 — 视觉一致性、边界情况、响应式、可访问性 |

### 命令

快速访问常用工作流的斜杠命令：

| 命令 | 用途 |
|------|------|
| `/plan` | 写代码前创建实施计划 |
| `/review` | 代码质量和安全审查 |
| `/security-check` | 专项安全审计 |
| `/test` | 运行测试检查覆盖率 |
| `/polish` | 视觉打磨和边界情况处理 |
| `/ship` | 部署前检查和部署 |

### 技能

增强工作流各阶段的模块化技能：

| 类别 | 技能 | 用途 |
|------|------|------|
| **设计** | 头脑风暴 | 通过苏格拉底式对话精炼设计（硬门禁） |
| **设计** | 编写计划 | 创建详细实施计划 |
| **设计** | 子智能体开发 | 用独立子智能体执行计划 |
| **开发** | 测试驱动开发 | 红-绿-重构循环 |
| **开发** | 完成前验证 | 确保工作真正完成 |
| **审查** | 请求代码审查 | 结构化审查流程 |
| **审查** | 接收代码审查 | 建设性地回应反馈 |
| **优化** | 模型选择 | 为每个任务选择合适的模型 |
| **优化** | 上下文窗口管理 | 优化上下文窗口使用 |

## 使用示例

```
你：我想做一个习惯打卡工具

AI（作为联合创始人）：好想法。在动手之前，我想先搞清楚几件事：
1. 你现在怎么记录习惯？痛点是什么？
2. 只给你自己用，还是也想分享给别人？
3. 最小可用版本长什么样？
4. 你有多少时间？

你：我用表格记录，太丑了而且老忘。
只给我自己用，只要一个 streak 计数器和每日提醒。
这个周末。

AI：明白了。这是 v1 计划：

## PRD.md
- 核心功能：打卡、streak 计数、每日提醒
- 黑名单：社交功能、数据同步、历史统计
- 验收标准：点击打卡 → streak+1，连续7天 → 显示成就

## DESIGN.md
- 主色调：#3B82F6（蓝色）
- 组件：卡片式布局，圆角12px
- 状态：加载骨架屏、空状态插画、错误toast

## ARCHITECTURE.md
- 技术栈：Vite + React + localStorage
- 目录：src/components, src/hooks, src/utils
- 禁止：不得使用class组件，不得引入后端

## TODO.md
- [ ] 1. 基础打卡功能（主流程+加载+空+报错）
- [ ] 2. Streak 计数逻辑
- [ ] 3. 每日提醒（浏览器通知）
- [ ] 4. 打磨（动画、响应式、可访问性）
- [ ] 5. 部署

要继续吗？

你：继续

AI：开始第一个任务。修改范围：src/components/CheckIn.tsx
不允许破坏：localStorage 数据结构
验收标准：点击按钮 → 数据保存 → 页面刷新后数据仍在

[开发中...]

AI：任务完成。测试清单：
✅ 主流程：点击打卡 → streak 显示
✅ 加载：页面加载时显示骨架屏
✅ 空状态：无打卡记录时显示引导
✅ 报错：localStorage 满时显示友好提示
✅ 边界：快速连续点击不重复计数

要 commit 吗？

你：是

AI：git commit -m "feat: 基础打卡功能通关"
```
